# 短视频发布稿

这份文档只解决一件事，把 `job-hunter` 讲清楚，并且能直接拿去拍小红书、抖音视频。

## 内容主线

| 方向 | 要讲什么 | 目标 |
|---|---|---|
| 这个项目能干什么 | 把招聘官网岗位自动整理成投递手册 | 先让人觉得有用 |
| 如何使用这个项目 | 给链接和简历，跑完就出结果 | 再让人觉得不难 |

## 视频 1，项目能干什么

| 项目 | 内容 |
|---|---|
| 适合平台 | 小红书、抖音 |
| 建议时长 | 35 秒到 45 秒 |
| 视频目标 | 让用户 10 秒内明白这不是普通爬虫 |
| 标题候选 | 我把招聘官网做成了投递手册 / 一个把岗位列表变成求职手册的开源项目 / 找工作时，我最想要的不是更多岗位，而是更清楚的排序 |
| 封面文案 | 把岗位列表变成投递手册 |

### 口播稿

| 时间 | 画面 | 口播 |
|---|---|---|
| 0-5 秒 | 快速切招聘官网长列表，再切成生成后的手册页 | 找工作最烦的，不是没岗位，是岗位太多，信息太散。 |
| 5-10 秒 | 放流程图 `assets/flow-map.svg` | 所以我开源了一个项目，叫 `job-hunter`。 |
| 10-20 秒 | 依次闪过抓取、匹配、报告三个阶段 | 它会先把招聘官网的岗位抓下来，再结合你的简历做匹配，最后直接生成一份投递手册。 |
| 20-30 秒 | 放 `assets/handbook-preview.svg` 或公开示例页 | 你拿到的不是一堆链接，而是一份排好优先级的岗位清单。哪个城市更适合你，哪些岗位更该先投，一眼就能看出来。 |
| 30-40 秒 | 切回仓库首页和开源地址 | 这东西现在已经开源了，你可以自己改规则、换网站、换简历，直接跑出属于你的版本。 |

### 结尾字幕

| 类型 | 文案 |
|---|---|
| 抖音 | 开源地址我放简介，想看完整效果直接看公开示例页 |
| 小红书 | 想要我下一条讲怎么用，评论区打一个「教程」 |

## 视频 2，如何使用这个项目

| 项目 | 内容 |
|---|---|
| 适合平台 | 小红书、抖音 |
| 建议时长 | 45 秒到 60 秒 |
| 视频目标 | 让用户觉得这个项目真能跑起来 |
| 标题候选 | 这个开源求职项目怎么用 / 3 步跑出你的岗位投递手册 / 给一个链接和一份简历，自动出结果 |
| 封面文案 | 3 步跑出投递手册 |

### 口播稿

| 时间 | 画面 | 口播 |
|---|---|---|
| 0-6 秒 | 先给最终结果页 | 如果你只想知道怎么用，这个项目其实就三步。 |
| 6-15 秒 | 放 README 里的 Quick Start 命令 | 第一步，装依赖。第二步，复制一份用户配置，把你的简历路径和目标城市填进去。 |
| 15-25 秒 | 放 `config/user.example.yaml` 关键区域 | 比如你想投上海、杭州，想找算法或者开发岗位，都可以提前写好。 |
| 25-38 秒 | 放运行命令 `python3 run.py --url ... --resume ...` | 第三步，给它一个招聘官网链接，再给它一份简历，直接运行。 |
| 38-50 秒 | 放流程图和输出结果 | 它会自动抓岗位、做匹配、生成 HTML 或 PDF 手册。最后你只要按分数高低开始投。 |
| 50-60 秒 | 切公开示例页和仓库地址 | 如果你想先看效果，不想自己跑，仓库里已经放了公开示例，可以直接打开看。 |

### 屏幕字幕

| 时间 | 字幕 |
|---|---|
| 0-6 秒 | 结果先看 |
| 6-15 秒 | 装依赖 |
| 15-25 秒 | 填配置 |
| 25-38 秒 | 跑命令 |
| 38-50 秒 | 自动出手册 |
| 50-60 秒 | 公开示例可直接看 |

## 视频 3，真实使用场景版

| 项目 | 内容 |
|---|---|
| 适合平台 | 小红书优先，也可发抖音 |
| 建议时长 | 50 秒左右 |
| 视频目标 | 从痛点切入，提升转发和收藏 |
| 标题候选 | 海投前，先别急着一个个翻岗位 / 校招岗位太多时，我怎么先排优先级 / 求职时真正缺的不是信息，而是决策顺序 |
| 封面文案 | 先排优先级，再投 |

### 口播稿

| 时间 | 画面 | 口播 |
|---|---|---|
| 0-8 秒 | 招聘官网连续翻页 | 很多人找工作会卡在第一步，不是不会投，而是不知道先投哪个。 |
| 8-18 秒 | 简历、城市偏好、目标岗位几个词飞入画面 | 因为每个人的简历不一样，城市不一样，方向也不一样。 |
| 18-30 秒 | 三步流程图 | 所以这个项目干的事，不是帮你找更多岗位，而是先把岗位按你的条件排一遍。 |
| 30-42 秒 | 手册结果页特写 | 最后它会给你一份更像行动清单的结果，你今天先投什么，哪些岗位值得保留，一下就顺了。 |
| 42-50 秒 | GitHub 仓库和公开示例页 | 这套东西我已经开源了，如果你最近刚好在找工作，可以直接拿去试。 |

## 拍摄建议

| 项目 | 建议 |
|---|---|
| 画面顺序 | 先结果，后过程，不要一上来先讲代码 |
| 素材优先级 | 公开示例页 > README 流程图 > 配置文件 > 命令行 |
| 口播语速 | 保持偏快，但每句只讲一个意思 |
| 字幕风格 | 一行一句，不要堆满屏 |
| 评论区引导 | 想看教程 / 想看支持哪些网站 / 想看真实跑一次 |

## 发布顺序

| 先发什么 | 原因 |
|---|---|
| 先发视频 1 | 先讲价值，最容易让人停留 |
| 再发视频 2 | 用户知道有用后，才会关心怎么用 |
| 最后发视频 3 | 用场景把人群收窄，更容易带来收藏和转发 |
