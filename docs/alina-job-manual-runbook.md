# 阿离岗位投递手册生成流程

## 适用场景

当用户给出岗位投递链接库和简历目录，需要生成一份可直接投递的岗位手册时，按这个流程走。

## 正确流程

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 1 | 读取 `CONTEXT.md` 和 `lessons.md` | 确认不要重复踩坑 |
| 2 | 从 Word 链接库提取表格、超链接、城市、关键词、平台 | 搜索入口结构 |
| 3 | 读取简历文本；图片型 PDF 先渲染成图片再人工读重点 | 求职画像 |
| 4 | 只抓公开可验证来源，优先智联招聘 | 原始 HTML 缓存 |
| 5 | 解析岗位标题、公司、薪资、地点、经验、学历、标签、链接 | 岗位 JSON |
| 6 | 只用岗位本身信息打分，不把搜索关键词并入匹配文本 | 干净的岗位清单 |
| 7 | 抽查高分和低分岗位，发现噪音就收紧规则后重算 | 最终筛选结果 |
| 8 | 用 HTML 保存完整可点击清单，再导出 PDF | 桌面交付文件 |

## 筛选硬规则

| 规则 | 原因 |
|---|---|
| 标题必须命中目标方向 | 平台标签会泛化，标题不对就不投 |
| 排除销售、客服、招商、地推、骑手、司机、普工 | 这些不是简历主方向 |
| 排除明显资深岗位和经验要求过高岗位 | 用户是应届/初级画像 |
| 前端、小程序、Node 只保留实习、经验不限或 1 年以下 | 避免混入重开发岗位 |
| 新人友好只看经验不限、应届、实习、校招、1年以下、专人带教 | 学历不是新人友好信号 |

## 不要做

| 不要做 | 原因 |
|---|---|
| 不要把搜索关键词并入岗位匹配文本 | 会制造 AI/AIGC 假命中 |
| 不要把未验证平台结果混入手册 | 用户会拿到打不开或不真实的岗位 |
| 不要用 DOCX 大表作为最终交付 | 大表渲染不稳定，HTML/PDF 更可靠 |
| 不要为了凑数量放宽标题方向 | 手册价值来自可投，不是数量大 |

## 反爬处理方案

| 平台 | 状态 | 正确处理 |
|---|---|---|
| 智联招聘 | 可自动抓取 | 作为默认数据源，解析公开 HTML 岗位卡片，落缓存后筛选 |
| BOSS直聘 | 需要登录态浏览器 | 不直接抓公开 HTML；只有用户开启浏览器调试并登录后，才从可见页面抽取 |
| 拉勾招聘 | 需要登录态浏览器 | 只作为备用入口；未验证岗位卡片前不入库 |
| 前程无忧 | 需要动态渲染验证 | 公开 HTML 常是应用壳，必须浏览器渲染后确认有岗位卡片 |
| 猎聘 | 需要动态渲染验证 | SEO 页面和真实岗位列表可能不一致，未验证前不入库 |
| 应届生求职网 | 旧入口失效 | 旧链接返回 404，后续改用站内新搜索 |

核心原则：不绕过平台风控，不伪造数据；只收录已经能看到、能解析、能打开的岗位。
